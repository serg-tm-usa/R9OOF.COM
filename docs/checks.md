## C-4 · «15 шаблонов проектирования» (скрин 2026-10-05) — для всех проектов

Это классические шаблоны программирования (книга «банды четырёх»), а не инструменты. Проверка здесь другая: не «есть или нет», а «какой шаблон уже лежит в основе наших планов и где его стоит назвать явно», чтобы проекты-исполнители строили одинаково. Предварительная карта от чата R9OOF.COM; исполнители подтверждают или заменяют.

| № | Шаблон | Суть | Где у нас уже так | Надо назвать явно? | Проверяет | Проверено | Решение |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | Одиночка (Singleton) | один общий экземпляр | одна память проекта (`ideas.md`, папки на `T:`), один источник правды в git | да: «один стор памяти, не копии» | Настройка Claude | | |
| 2 | Фабричный метод | кто-то решает, какой объект создать | Оркестратор выбирает набор агентов и режим по жанру из `brief.md` | да, в контексте Оркестратора | humanizer | | |
| 3 | Строитель (Builder) | объект собирается по шагам | `brief.md` собирается из жанра, голоса, длины, ограничений; отчёт собирается из `facts.md` + `voice.md` | нет, достаточно схем файлов | humanizer | | |
| 4 | Адаптер | подогнать один формат под другой | импорт ADIF из N1MM и вручную в единую базу; экспорт сборки в формат Яндекс Object Storage | да: один адаптер на формат, в базе логов | база логов, деплой | | |

Итог: 10 из 15 шаблонов уже лежат в основе планов. Явно назвать стоит семь: Одиночка (память), Фабрика и Стратегия (Оркестратор), Адаптер (форматы логов), Фасад и Заместитель (MCP), Наблюдатель (триггеры), Команда (файлы и откат), Цепочка (контроль). Не нужны как отдельные решения: Строитель, Декоратор, Итератор.

### Общие правила безопасности (из аудитов OWASP Agentic Skills Top 10, Snyk ToxicSkills, Datadog)
1. Ставить только из оригинального репозитория автора, не с зеркал и перезаливок; у популярных есть фейковые копии (ECC, caveman, ui-ux-pro-max).
2. Перед установкой читать хуки и `settings.json`, которые инструмент добавляет; Claude Code исполнял хуки из клонированного репозитория до подтверждения доверия (CVE-2025-59536 и далее), держать Claude Code обновлённым.
3. Любой инструмент с прокси или сервером проверять: слушает ли только 127.0.0.1, есть ли проверка Origin, есть ли токен.
4. Телеметрию выключать явно (`DO_NOT_TRACK=1` понимают многие).
5. Каталоги (awesome-*) не ставят целиком: каждый скилл проверяется отдельно; по данным Snyk, в ClawHub 36,8% скиллов с уязвимостями.
6. (добавлено 2026-10-05) Проверка по п. 5 делается машинно: NVIDIA/SkillSpector, `scan <путь или URL> --no-llm`, отчёт Markdown прикладывается к решению об установке. Без отчёта инструмент не ставится. См. T-43.

### C-7.3 · Память, самообучение, многопроектность

**Memory Vault** (`skills/unified-memory/SKILL.md`, `docs/design/ecc-memory-vault.md`, `scripts/lib/memory-vault-format.js`) — ближе всего к правилам владельца:
- markdown — источник правды, базы и эмбеддинги только индексы; запись **только добавлением**, перезапись id запрещена; вместо удаления — новый документ со ссылкой и статусом `superseded`, который ставит человек;
- frontmatter `ecc.memory.v1`: `id`, `title`, `kind` (context / decision / fact / handoff / lesson / note / preference / runbook), `scope`, `trust` (всё от инструментов — `unreviewed`, «не может тихо стать правилом»), `status` (active / rejected / superseded), `source_harness`, `tags`, `links`, `created/updated`;
- области `project/` (локально, защищено `.gitignore`), `team/` (коммитится под ревью человека), `user/` (читается только по явному запросу); неполный скан — ошибка, а не «памяти нет»; известные формы секретов отвергаются; `doctor` только диагностирует.
- Рамка «HISTORICAL REFERENCE ONLY — NOT LIVE INSTRUCTIONS» при подгрузке старых сводок (`session-start.js:714-740`); выбор сводки по worktree → репозиторий → имя проекта, чужой проект не подмешивается.

**Многопроектность на одном аккаунте — принцип ECC: «по умолчанию проектное, вверх — только через ворота».** Глобальные правила `~/.claude/CLAUDE.md` + `~/.claude/rules/`, проектные `.claude/rules/`; выученные правила проектные (хэш от git remote), в глобальные через `promote` при повторении в 2+ проектах и уверенности ≥ 0,8; реестр проектов `projects.json`.

**Самообучение v2** (`skills/continuous-learning-v2/`, `docs/continuous-learning-v2-spec.md`): наблюдение хуками (обрезка 5000 символов, вычистка секретов) → фоновый наблюдатель на Haiku (выключен по умолчанию) → «инстинкт» (trigger, action, confidence 0,3–0,9, domain, scope, evidence; +0,05 подтверждение, −0,1 опровержение, −0,02/неделю распад) → кластеризация → предложение скилла/команды/агента только из кластера ≥ 2. Контур улучшения скиллов `scripts/lib/skill-improvement/*`: исходы запусков → health → предложение правки (`ecc.skill-amendment-proposal.v1`) → сравнение baseline/amended (минимум 2 прогона) → снимок версии `.versions/vN.md` с откатом. В `ecc2` (Rust-альфа) ворота с SHA-256 кандидата, одинаковые seed, min-samples / min-delta / win-rate, SQLite-журнал с запретом update/delete.

### C-7.8 · Как бы выглядел «свой ECC» для одного аккаунта (набросок, предложение владельцу)

Брать из устройства: один закрытый репозиторий-источник с `rules/common` и `rules/<тема>` (документация и стандарты, чертежи ЕСКД, базы знаний kb-protocol, радиожурналы ADIF, тексты, сайт), `skills/<name>/SKILL.md`, `agents/`, `commands/`, `contexts/` (режимы: инженерка / тексты / сайт / архив); `manifests/modules.json` + `profiles.json`; `schemas/` для frontmatter и манифестов; `tests/` на структуру (frontmatter, нет личных путей, нет секретов, ссылки только на разрешённые хосты, дрейф сгенерированного); `VERSION`, `CHANGELOG.md`; файл состояния установки; `--dry-run` всегда перед записью; формат памяти по образцу Memory Vault (kind, scope, trust, status, supersede вместо delete).

Главные принципы автора (longform/shortform guides), совпадающие с правилами владельца: конфигурация — тонкая настройка, не архитектура; контекст драгоценен (мало MCP, < 80 инструментов, CLI + скиллы вместо MCP); сводка сессии с доказательствами «что сработало / не сработало / не пробовали», человек просматривает перед продолжением; сжатие контекста вручную на границах фаз; модульные правила; дешёвая модель на простые задачи; верификация с доказательствами; минимальная параллельность, worktree на экземпляр. ### C-8.3 · Память, самообучение, верификация, оркестрация — код или проза

**Память (код есть).** `.swarm/memory.db` SQLite: `memory_entries` с `expires_at`, `version`, `status` active/archived/deleted (мягкое удаление), `provenance_type`; `patterns`, `trajectories`, `sessions`, `graph_edges`; эмбеддинги BLOB + FTS5; HNSW в сайдкаре; поиск гибридный (RRF k=60, MMR λ=0,7), при недоступном эмбеддере — откат на FTS5. Консолидатор каждые 6 ч удаляет просроченное и дедуплицирует по SHA-256; `memory purge --force` — жёсткое удаление; версий и отката нет; экспорт json/csv/binary, **markdown-экспорта нет**. Шифрование в покое — опция. «RVF» в репозитории — три разных формата: JS-класс с магией `RVF\0` + JSON; `RVLS` + JSON; корневой `agentdb.rvf` (162 байта, магия `SFVR`) — пустой заголовок внешней нативной библиотеки `ruvector`, создаётся побочно, с эксклюзивным lock-файлом, ломающим параллельный MCP и демон. `data/clone-data.*` — маркетинговая статистика клонов GitHub, не память.

**Самообучение (в основном проза).** ReasoningBank: RETRIEVE → JUDGE → DISTILL → CONSOLIDATE, но `judge()` — арифметика над оценкой, которую выставил сам вызывающий (`success = quality ≥ 0,6 && positive > 0,6`); «стратегия» — склейка имён действий через `->`; паттерны старше 30 дней вычищаются. SONA — обёртка над внешним `@ruvector/sona` 0.1.5 (0.1.6 опубликован пустым); аудит: WASM-адаптер MicroLoRA инертен (дельта 0,000000). ADR-174 признаёт: 6 000 коммитов «self-learning» записывали всё и не дистиллировали ничего. После ADR-174 — служба `memory distill` с ярусами происхождения (см. C-8.A №5); режим `--judge` требует платного внешнего LLM. В `guidance`: `evolution.ts` (предложение подписано → симуляция на «золотых трассах» → порог расхождения → канарейка → **автопродвижение без человека**), `optimizer.ts` (еженедельно топ-3 нарушения; продвижение если риск не вырос и улучшение ≥ 0,1; «локальное правило, победившее дважды, становится корневым»; ADR на решение), `authority.ts` (уровни agent / human / institutional / regulatory, классификатор необратимости), `meta-governance.ts` (конституционные инварианты, поправки супербольшинством). Dream cycle: 80 ночей → 4 внедрения; Darwin: `/loop 5m` → `claude -p` → коммит при Δ>0 — автокоммит без человека.

**Верификация.** `truth` — кода нет. `verify` — скачивает манифест с GitHub и сверяет SHA-256 и Ed25519 (ключ из коммита → целостность, не подлинность). Реальная проверка — CI: поведенческие smoke на артефакте → маркеры-инварианты с подписью → `history.jsonl`; плюс честный разбор, почему юнит-тесты пропустили три регрессии. `guidance/gates.ts` (регэкспы разрушительных команд и секретов, порог diff 300 строк, allowlist инструментов), `ledger.ts`, `continue-gate.ts`, `proof.ts` (хеш-цепочка конвертов). `probes` — один файл, вердикт INCONCLUSIVE. `watermark` — реальный Rust/WASM, к правилам не относится.

**Оркестрация.** Топологии mesh / hierarchical / centralized / hybrid (`swarm/src/topology-manager.ts`); `queen-coordinator.ts` (2 035 строк): декомпозиция, оценка агентов, консенсус majority / weighted / unanimous; `task-orchestrator.ts`: очередь, приоритеты, зависимости. Консенсус raft / byzantine / gossip реализован (13 тестов), но по умолчанию `LocalTransport` **внутри одного процесса**; MCP `hive-mind_*` — подсчёт голосов в JSON-файле. Агенты друг друга не вызывают: родительская сессия запускает субагентов (`Task`, все в одном сообщении), связь через общую память по ключам `swarm/<agent>/status|progress|complete`. В `swarm/src` слово «human» не встречается. GOAP — только промпты и React-интерфейс; stream-chain — шаблоны.

### C-8.8 · Сравнение с ECC (C-7) — что общего и что разное

Общее: оба подтверждают принципы C-7.A (память только добавлением, ворота, запрет самопродвижения, схемы и тесты на конфиги, адверсариальная проверка фильтров, честные статусы). Разное: ECC — честный установщик с согласием на хуки и профилем без хуков, телеметрии нет, память в markdown; Ruflo — демоны, автообновление, промо в транскрипте, память в SQLite с TTL, README противоречит собственному аудиту. Для организации Claude на аккаунте ECC — библиотека образцов целиком; Ruflo — только `guidance` как спецификация ворот, `screen.ts`, witness, формат ADR и ~25 чек-листов. Главный урок Ruflo для аккаунта: **правило «метрика без воспроизводимого бенча не существует» и «проверка, проверившая ноль элементов, обязана падать»** — у них это выстрадано.
