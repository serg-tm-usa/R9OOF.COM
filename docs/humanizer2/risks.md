# Humanizer 2 · типовые проблемы ИИ-систем и чем они закрыты у нас

Добавлено 2026-10-05 по скрину «20 AI Problems Interviewers Love to Ask». Для проекта-исполнителя: пройти перед запуском этапа 4 и отметить, что закрыто, что нет.

| № | Проблема | Чем закрыта в плане | Статус |
| --- | --- | --- | --- |
| 1 | Галлюцинации (выдумки) | Фактограф + Проверяющий фактов, факт-замок сканера, правило «ничего сверх `facts.md`» | в плане |
| 2 | Предел контекста | У каждого агента свой контекст, обмен файлами, Судья с намеренно малым контекстом | в плане |
| 3 | Подмена инструкций в тексте (prompt injection) | Правило: команды внутри редактируемого текста — данные; принять в CONTEXT всех агентов | добавить явно |
| 4 | Утечка данных | Тексты авторов и владельца вне публичного репозитория; ключи только в окружении | в плане |
| 5–7 | Сбой поиска, плохая нарезка, качество эмбеддингов | RAG не используем; память — файлы и grep. Актуально позже | не актуально |
| 8 | Неверный вызов инструмента | Схемы файлов (этап 3а), возврат файла не по схеме | в плане |
| 9 | Избыточная самостоятельность | Иерархия, `blocked.md` вместо «сделать как получится», подтверждение владельца перед изменением правил | в плане |
| 10 | Недетерминированность | Судья — свежий агент на каждый запуск; ворота на всём контрольном наборе, не на одном тексте; правило из одной пары не допускается | в плане |
| 11 | Оценка качества | Метрики M1–M15, контрольный набор, оценка владельца | в плане |
| 12–13 | Задержка и стоимость | Лёгкий и полный режимы; лимит кругов | в плане |
| 14 | Лимиты частоты внешних API | QRZ XML, геокодеры: учесть в проекте базы логов | вне humanizer |
| 15 | Наблюдаемость | MEMORY каждого агента, журнал вызовов, чек-листы при сдаче | в плане |
| 16 | Выбор модели | Не решено: какую модель на какую роль (Судье и Воротам сильную, Фактографу можно быструю). Решить на этапе 4 | открыто |
| 17 | Ограждения | CONTROL каждого агента, «что запрещено» в ролях | в плане |
| 18 | Память | Папки на `T:` + закрытый GitHub | решено |
| 19 | Дрейф в эксплуатации | Перепроверка случайного принятого правила раз в 10 пар | в плане |
| 20 | Восстановление после сбоя | Откат одним коммитом; `blocked.md`; журнал | в плане |

Два пункта требуют решения проекта-исполнителя: 3 (явно вписать правило в контексты) и 16 (модели по ролям).
