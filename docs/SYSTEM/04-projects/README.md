# 04-projects · слой проекта

### Шаг 5. `04-projects/` — слой проекта (предметное, отделённое от универсального)

```
SYSTEM/04-projects/
  README.md                            реестр проектов: имя, назначение, какие пакеты правил подключены, где его память, статус
  _template/
    brief.md                           задача, жанр, площадка, лимиты, адресат, режим (лёгкий / полный), подключаемые пакеты правил
    voice.md                           профиль голоса автора для этого проекта (6 измерений, статус профиля, конфликты)
    glossary.md                        термины предметной области и «что с чем не путать»; allowlist сокращений
    facts.md                           факты текущей задачи (с защищёнными оговорками автора и уровнем утверждений)
    MEMORY.md                          память проекта (тот же формат, что в 03-memory/schema.md, scope=project)
    CONTROL.md                         проверки проекта, критерии приёмки, кто пишет
    TODO.md                            задачи проекта с машинным контролем (номер, источник, исполнитель, критерий, проверено чем, статус, дата)
    adr/                               решения проекта: NNNN-<кратко>.md (контекст / варианты / выбор / следствия; статус proposed → accepted → superseded)
  <project-1>/ …                       по одному каталогу на проект; создаёт владелец
```
- Пишет: владелец и чат проекта; универсальные агенты читают `brief/voice/glossary/facts` на входе и не меняют их.
- Источник: правило владельца «скилл универсален, слой проекта отдельно» (ideas.md «Решения»), `humanizer2/agents.md` §0, ARS Schema 10 (Style Profile) и Material Passport (только `content_hash`, `verification_status`), C-7.A №19 и C-8.A №17 (ADR), правило «отдельный план = PLAN/MEMORY/CONTROL».
- Запрещено: предметное из проекта уходит в `01-rules/common` или в карточки агентов.
