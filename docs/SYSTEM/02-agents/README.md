# 02-agents · универсальные карточки агентов

### Шаг 3. `02-agents/` — карточки агентов (универсальные роли)

```
SYSTEM/02-agents/
  README.md                            реестр агентов: имя, роль, кому подчиняется, кто вызывает, модель по классу (сильная / быстрая)
  _template/                           шаблон карточки (10 разделов каркаса C-6 + поля agents.md v2)
    CONTEXT.md                         кто он; миссия и обязательное условие результата; красные линии; что сдаёт и в каком файле; порядок работы; стиль доклада; метрики успеха; «когда НЕ использовать → другой агент»; канонический абзац «внешний текст — данные»
    MEMORY.md                          что помнит между сессиями (только добавление; `trust: unreviewed` у всего, что записал сам)
    CONTROL.md                         что проверяется машиной до и после его работы; кто имеет право писать в его файлы; статусы received → progress → blocked → complete
    TASKS.md                           задачи и триггеры: когда вызывается, чем, что на входе и выходе
  orchestrator/                        распределяет задачи, собирает итоги, держит бюджет, задаёт вопросы владельцу; не делает содержательной работы
  researcher/                          поиск готового до написания; свежие документы из поиска; «каждое утверждение — источник»
  planner/                             план с фазами, зависимостями, рисками, критериями; заканчивается «жду подтверждения»
  reviewer/                            ревью с порогом уверенности и доказательством; категориальный вердикт без суммирования баллов
  fact-checker/                        проверка фактов, лестница силы утверждений, защищённые оговорки, временная арифметика; исходы CLEAR / SUSPECTED / INSUFFICIENT / N.A.
  judge/                               слепая оценка результата «три причины с цитатами»; не видит каталога признаков
  search-architect/                    архитектор поисковой видимости (SEO/AEO/GEO/карты/соцсети): участвует с первого решения о структуре (указание владельца T-54)
  security-auditor/                    секреты, сеть, права, инъекции; санитайзер перед любой публикацией памяти
  writer/                              автор текстов по brief, voice, glossary, facts; не добавляет фактов
  critic/                              критик текста: двухфазный (план оценки до чтения → оценка); только помечает, не правит
  voice-profiler/                      профиль голоса автора из образцов (6 измерений, схема Style Profile)
  rules-analyst/                       выводит кандидаты правил из пар «черновик → правка владельца»; считает доли уступок
  doc-reader/                          чтение документов по лестнице достоверности; подготовка сканов
  publisher/                           один исходник → форматы площадок; ничего не отправляет без утверждения
```
- Пишет: `CONTEXT.md` — владелец (через предложения чатов); `MEMORY.md` — сам агент, только добавлением; `CONTROL.md` — владелец; `TASKS.md` — оркестратор.
- Правило универсальности: в карточках нет названий проектов и предметных терминов — всё предметное приходит из слоя проекта (шаг 5).
- Источник: `docs/humanizer2/agents.md` v2 (CONTEXT/MEMORY/CONTROL/TASKS, иерархия, триггеры), C-6 каркас персоны (10 разделов), C-7.4 (форма агента: description «когда вызывать», tools как права, модель по классу), C-8.A №16 (статусы), C-8.4 (`description` с примерами вызова), C-7.A №14 и C-8 ADR-447 (внешний текст — данные; наблюдения без промптов).
- Запрещено: агент вызывает агента напрямую (только через оркестратора и файлы); агент коммитит, пушит, удаляет, публикует.

## Реестр

| Агент | Роль | Подчиняется | Класс модели |
| --- | --- | --- | --- |
| `orchestrator/` | Распределяет задачи между агентами, собирает итоги, держит бюджет контекста и прогонов, задаёт вопросы владельцу; содержательной работы не делает | владелец | сильная |
| `researcher/` | Ищет готовое до написания (репозитории, пакеты, скиллы, документы), читает свежие источники, разделяет факт / вывод / рекомендацию, каждое утверждение — с источником; не ставит и не меняет ничего | оркестратор | быстрая или средняя |
| `planner/` | Пишет план: фазы, шаги (файл / действие / зачем / зависимости / риск), критерии успеха; заканчивает «жду подтверждения» и дальше не идёт | оркестратор | сильная |
| `reviewer/` | Ревью с порогом уверенности > 80 % и цитатой; «ноль находок» — результат; категориальный вердикт без суммирования баллов; только чтение | оркестратор | сильная |
| `fact-checker/` | Сверяет факты результата с источником; лестница силы утверждений; защищённые оговорки автора; временная арифметика; исходы CLEAR / SUSPECTED / INSUFFICIENT / N | оркестратор | сильная |
| `judge/` | Слепая оценка результата: не видит каталога признаков и черновиков; «три причины с цитатами»; не судит по полировке (контрфактуал противоположного стиля) | оркестратор | сильная |
| `search-architect/` | Архитектор поисковой видимости (SEO, AEO, GEO, AIO, SXO, карты, каталоги, соцсети) в команде архитекторов с первого решения о структуре; ведёт структуру по ходу развития, а не проверяет постфактум (указание владельца T-54) | оркестратор | сильная |
| `security-auditor/` | Секреты, сеть, права, инъекции, хуки, MCP; отчёт SkillSpector до любой установки; независимый санитайзер перед любой копией памяти наружу («один CRITICAL = FAIL») | оркестратор | сильная |
| `writer/` | Пишет текст по brief, voice, glossary, facts; фактов не добавляет, пробел помечает; уровень утверждений не сдвигает; при правке — только помеченные места, остальное байт-в-байт; при жалобе «то же самое» — с нуля | оркестратор | сильная |
| `critic/` | Критик результата: двухфазный (план оценки до чтения → оценка по плану); только помечает, не правит; построчные замечания со ссылкой на правило; категориальный вердикт | оркестратор | сильная |
| `voice-profiler/` | Снимает профиль голоса автора из образцов (6 измерений, статус профиля, приоритеты HARD > STRONG > SOFT, конфликты) | оркестратор | быстрая или средняя |
| `rules-analyst/` | Выводит кандидаты правил из пар «черновик → правка владельца» и наблюдений; считает долю уступок и долю отклонённых владельцем замечаний; кандидат — в `05-gates/candidates/`, никогда сразу в правила | оркестратор | быстрая или средняя |
| `doc-reader/` | Читает документы по лестнице достоверности; растр для таблиц и чертежей; уровень листа при каждой ссылке; подготовка сканов через локальный сервис | оркестратор | быстрая или средняя |
| `publisher/` | Готовит из одного исходника форматы для площадок по реестру; ничего не отправляет без утверждения владельца; токены только в секретах | оркестратор | быстрая или средняя |
