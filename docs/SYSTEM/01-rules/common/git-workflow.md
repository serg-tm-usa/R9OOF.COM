# Общее правило: git

1. Одна ветка для работы, одна для выпуска; в выпуск только слиянием после проверки сборки.
2. Формат коммита: `<тип>: <что сделано>`; типы feat / fix / refactor / docs / test / chore; тема до 72 знаков.
3. Один коммит — одно правило или одно изменение; смешивать нельзя.
4. Историю не переписывать: никакого rebase, amend, force-push на чужих ветках; на своих — только по правилу проекта.
5. Коммит и push — только по слову владельца; агент готовит, человек подтверждает.
6. Перед коммитом: нет секретов, нет личных путей, нет отладочного вывода; проверка проходит.
7. Удаление файлов и веток — только по явному решению владельца, с записью причины.

Источник: ECC `rules/common/git-workflow.md`, агент `git-workflow-master` (C-7); Ruflo `templates/github-pr-manager.md`, `swarm/maintenance.md` (C-8.4); решение владельца «один коммит — одно правило».
