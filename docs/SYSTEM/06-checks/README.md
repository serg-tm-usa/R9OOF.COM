# 06-checks · машинный контроль

### Шаг 7. `06-checks/` — машинный контроль и проверочные списки

```
SYSTEM/06-checks/
  README.md
  checklists/                          проверочные списки по темам (из checks.md C-1…C-8): seo-22.md, ai-problems-20.md, web-attacks-10.md, design-patterns-15.md, tool-safety.md, persona-skeleton.md, mechanisms-account.md (C-7.A + C-8.A)
  schemas/                             JSON-схемы: frontmatter карточки агента, скилла, правила; формат памяти; формат gate-NN; формат TODO-строки; манифест инструментов
  tests/                               структурные проверки (описания, не код — код пишет исполнитель): «у каждого скилла есть name/description в одну строку», «нет личных путей», «нет секретов», «нет непиннованных ссылок», «сгенерированное совпадает с источником», «хуки имеют отпечаток», «проверка нуля элементов падает»
  baselines/                           ratchet-базлайны: число нарушений может только уменьшаться; число тестов — только расти
  adversarial/                         адверсариальный корпус для фильтров: секреты, разбитые невидимыми символами; длинные строки; доброкачественные двойники; файл известных дыр
  witness/                             манифест «маркер правила присутствует в файле» + история только добавлением
  reports/                             отчёты проверок с датой: PASS/FAIL по фазам, «вердикт одной строкой → блокеры → проверенные улики → следующее действие»
```
- Пишет: `checklists/` — владелец через предложения чатов; `schemas/`, `tests/`, `adversarial/` — исполнитель по указанию владельца; `reports/`, `baselines/`, `witness/` — только скрипты.
- Источник: `docs/checks.md` целиком, C-7.A №4–6, №15, C-8.A №9–13, ECC `scripts/ci/validate-*`, Ruflo `probe-mod-guards`, `ci-test-ratchet`, witness.
