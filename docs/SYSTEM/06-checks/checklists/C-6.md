## C-6 · The Agency (msitarzewski/agency-agents): разбор всех персон (2026-10-05)

Решение владельца: «Считывай все персоны и проверяй что нам надо». Прочитаны все 293 markdown-файла репозитория (~589 тыс. слов) пятью параллельными читателями по отделам. Правило отбора: **да** — персона становится образцом для нашего агента или чек-листа целиком; **образец** — берём одну-две структуры или приёма, не роль; **нет** — не наша область. Ничего не ставится: репозиторий читается с GitHub, установщик `install.sh` и `convert.sh` не запускаются (правило безопасности 1 и 2 из C-5).

### Устройство файла персоны (образец для `CONTEXT.md` наших агентов)
Один и тот же каркас у всех 293 файлов, стоит принять как форму для агентов Humanizer 2 и остальных проектов:
1. Шапка YAML: `name`, `description` (когда вызывать, с примерами), `color`, `emoji`, `vibe` — одна фраза характера.
2. Identity & Memory — кто агент, что помнит между сессиями, где лежит память.
3. Core Mission + «Default requirement» — обязательное условие результата, без которого работа не принимается.
4. Critical Rules — красные линии, нумерованный список.
5. Technical Deliverables — что именно сдаёт, в каком файле и формате.
6. Workflow Process — шаги по порядку, с условиями перехода.
7. Communication Style — как докладывает, объём, тон.
8. Learning & Memory — что записывает после каждой задачи, как обновляет свои правила.
9. Success Metrics — измеримые критерии.
10. Advanced Capabilities — что умеет сверх базового.
Наш `agents.md` v2 уже содержит пункты 2, 3, 6, 8; добавить нужно 1 (`description` с примерами вызова), 4, 5, 7, 9.

Рядом два реестра: `divisions.json` (отделы: имя, описание, список персон) и `tools.json` (17 инструментов-получателей с полями `format`, `installKind`, пути конфигов). Идея реестра годится для чата «Настройка Claude»: один файл-опись агентов и один файл-опись инструментов, из которых генерируются конфиги.
