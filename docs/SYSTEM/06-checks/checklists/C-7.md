## C-7 · everything-claude-code (affaan-m, «ECC») v2.2.3: что принципиально улучшит работу Claude на аккаунте владельца (2026-10-05)

Слово владельца: «Проверяй детально с прицелом не только на сайт, а вообще на настройку Клода, на всё, что надо вперёд… для перспективы развития Клода на моём аккаунте вообще… не только для существующей структуры, не только для существующих сайтов, а вообще для моего аккаунта, чтобы принципиально улучшить его работу». Поэтому раздел построен от аккаунта, а не от проектов: сначала C-7.A — принципы и механизмы, которые меняют работу Claude в любом чате владельца; потом справочные таблицы по устройству, агентам, командам, скиллам и правилам; в конце — предложение, куда что отправить. Прочитано четырьмя читателями: устройство и безопасность (install, hooks, manifests, schemas, scripts, CI); все 68 агентов и 94 команды; все 293 SKILL.md и 122 файла правил; память, самообучение, контексты, раздача на другие инструменты, тесты, руководства автора. Репозиторий MIT, 273 тыс. звёзд, последний коммит 01.10.2026, 103 МБ, 2790 md-файлов. Только чтение, ничего не ставилось. Прежний вердикт C-5 №6 («нет: перегруз контекста») дан был по заголовку; ниже — по чтению.

Легенда «нужно?»: **да** — брать и адаптировать; **общее** — полезно для организации Claude на аккаунте в целом, любому будущему проекту; **образец** — брать форму или приём, содержание переписывать; **нет** — не наше.

### C-7.0 · Итоговый вердикт (предложение владельцу)

| Вопрос | Ответ |
| --- | --- |
| Ставить целиком? | **Нет.** Полная установка держит в контексте ~40–45 тыс. токенов фона (одни описания 293 скиллов ≈ 28 тыс.); 24 хука, из которых несколько правят исходники, блокируют правки и ломают работу на Windows. |
| Ставить профиль `minimal` (без хуков)? | Возможно, позже и только после отчёта SkillSpector (T-43); но тогда от ECC остаются одни тексты, которые проще взять как образцы. |
| Безопасно? | Телеметрии «домой» нет (проверено по коду хуков и библиотек). Сеть — только по явным командам (релиз, auto-update, импорт по URL) и в `.mcp.json` (`npx -y chrome-devtools-mcp` — непиннованная загрузка). Установщик честный: `--dry-run`, явное согласие на хуки с перечислением их возможностей, файл состояния для полного удаления. Фейковые копии в сети есть — только affaan-m. |
| Что брать? | **Как библиотеку образцов** — лучшую из просмотренных: устройство (манифесты, схемы, тесты, профили, согласие на хуки), формат памяти (Memory Vault), контур самообучения с воротами, ~30 агентов/команд и ~60 скиллов/правил как формы для наших. Список ниже. |
| Что противоречит правилам владельца? | Хуки, меняющие файлы (`stop-format-typecheck`, `quality-gate`) и удаляющие (`/prune`, `refactor-cleaner`, удаление путей при смене профиля); сводки сессий, стираемые через 7 дней без версий; самообучение из каждого вызова инструмента и инжекция «инстинктов» на старте без утверждения; агенты, которые сами коммитят и пушат (`gan-generator`, `/santa-loop`); `auto-update` с `git pull`. |

Примечание по слову владельца («забрать всё полезное»): слой «для существующих чатов» не выброшен — он в C-7.4–C-7.7 (колонка «проект») и в C-7.9; слой «для аккаунта вообще» — C-7.A и C-7.1–C-7.3, C-7.8. Оба слоя действуют вместе.

### C-7.3 · Память, самообучение, многопроектность

**Memory Vault** (`skills/unified-memory/SKILL.md`, `docs/design/ecc-memory-vault.md`, `scripts/lib/memory-vault-format.js`) — ближе всего к правилам владельца:
- markdown — источник правды, базы и эмбеддинги только индексы; запись **только добавлением**, перезапись id запрещена; вместо удаления — новый документ со ссылкой и статусом `superseded`, который ставит человек;
- frontmatter `ecc.memory.v1`: `id`, `title`, `kind` (context / decision / fact / handoff / lesson / note / preference / runbook), `scope`, `trust` (всё от инструментов — `unreviewed`, «не может тихо стать правилом»), `status` (active / rejected / superseded), `source_harness`, `tags`, `links`, `created/updated`;
- области `project/` (локально, защищено `.gitignore`), `team/` (коммитится под ревью человека), `user/` (читается только по явному запросу); неполный скан — ошибка, а не «памяти нет»; известные формы секретов отвергаются; `doctor` только диагностирует.
- Рамка «HISTORICAL REFERENCE ONLY — NOT LIVE INSTRUCTIONS» при подгрузке старых сводок (`session-start.js:714-740`); выбор сводки по worktree → репозиторий → имя проекта, чужой проект не подмешивается.

**Многопроектность на одном аккаунте — принцип ECC: «по умолчанию проектное, вверх — только через ворота».** Глобальные правила `~/.claude/CLAUDE.md` + `~/.claude/rules/`, проектные `.claude/rules/`; выученные правила проектные (хэш от git remote), в глобальные через `promote` при повторении в 2+ проектах и уверенности ≥ 0,8; реестр проектов `projects.json`.

**Самообучение v2** (`skills/continuous-learning-v2/`, `docs/continuous-learning-v2-spec.md`): наблюдение хуками (обрезка 5000 символов, вычистка секретов) → фоновый наблюдатель на Haiku (выключен по умолчанию) → «инстинкт» (trigger, action, confidence 0,3–0,9, domain, scope, evidence; +0,05 подтверждение, −0,1 опровержение, −0,02/неделю распад) → кластеризация → предложение скилла/команды/агента только из кластера ≥ 2. Контур улучшения скиллов `scripts/lib/skill-improvement/*`: исходы запусков → health → предложение правки (`ecc.skill-amendment-proposal.v1`) → сравнение baseline/amended (минимум 2 прогона) → снимок версии `.versions/vN.md` с откатом. В `ecc2` (Rust-альфа) ворота с SHA-256 кандидата, одинаковые seed, min-samples / min-delta / win-rate, SQLite-журнал с запретом update/delete.

### C-7.8 · Как бы выглядел «свой ECC» для одного аккаунта (набросок, предложение владельцу)

Брать из устройства: один закрытый репозиторий-источник с `rules/common` и `rules/<тема>` (документация и стандарты, чертежи ЕСКД, базы знаний kb-protocol, радиожурналы ADIF, тексты, сайт), `skills/<name>/SKILL.md`, `agents/`, `commands/`, `contexts/` (режимы: инженерка / тексты / сайт / архив); `manifests/modules.json` + `profiles.json`; `schemas/` для frontmatter и манифестов; `tests/` на структуру (frontmatter, нет личных путей, нет секретов, ссылки только на разрешённые хосты, дрейф сгенерированного); `VERSION`, `CHANGELOG.md`; файл состояния установки; `--dry-run` всегда перед записью; формат памяти по образцу Memory Vault (kind, scope, trust, status, supersede вместо delete).

Делать иначе: память и состояние только на `T:` по kb-protocol с манифестом SHA-256 и копией в закрытом GitHub — не `~/.claude/sessions`, не `/tmp`; хуки только читающие и предупреждающие (exit 0), ни одного, который правит, блокирует или удаляет; никакого самообучения и подмешивания контекста на старте без явной команды; удаление не автоматизируется — в архив; обновление вручную, один коммит на одно правило; MCP только пиннованные и по решению владельца, никаких `npx -y …@latest` и `.mcp.json` в проектах; скиллы десятками, не сотнями, бюджет описаний ≈ 5 тыс. токенов, lean-профиль основной.

Главные принципы автора (longform/shortform guides), совпадающие с правилами владельца: конфигурация — тонкая настройка, не архитектура; контекст драгоценен (мало MCP, < 80 инструментов, CLI + скиллы вместо MCP); сводка сессии с доказательствами «что сработало / не сработало / не пробовали», человек просматривает перед продолжением; сжатие контекста вручную на границах фаз; модульные правила; дешёвая модель на простые задачи; верификация с доказательствами; минимальная параллельность, worktree на экземпляр. Противоречат: временные сводки с удалением; авто-сводки хуками без утверждения; учиться из каждого вызова инструмента.
